### 2-1. 關於 T-10 的判定方式（重要）

T-10 會將**非 `file://` 來源**的 console 錯誤降級為 INFO，不計入失敗。本次執行實際出現 2 筆此類訊息：

```
Failed to load resource: net::ERR_CONNECTION_RESET
```

來源為本環境封鎖 `fonts.googleapis.com`。此為**測試機的網路限制，非交付物的缺陷**。未捕捉的頁面例外（`pageerror`）**不受此降級規則保護**，一律判為失敗。

## 3. 補充程式化驗證

以下項目不在自動化腳本內，為補足 `03` 第 9、10 節中原本標記為「無法靜態確認」的疑慮而另行實測。

| 編號 | 驗證項目 | 方法 | 實測結果 | 判定 |
| --- | --- | --- | --- | --- |
| V-01 | 320px 寬的版面重排（SC 1.4.10） | Chromium 320×800，逐一量測所有非 fixed／absolute 元素的右緣 | `documentElement.scrollWidth` = 320、viewport = 320、無任何元素超出 | OK |
| V-02 | **停用 JavaScript 時的內容可見性** | `javaScriptEnabled: false` 載入後檢查 `.reveal` 的 computed opacity | 19 個元素中 **0 個** opacity < 0.99；`<html>` 未帶 `js` class | OK |
| V-03 | **列印時的內容可見性**（未捲動即列印） | `emulateMedia({ media: "print" })`，刻意不捲動 | 19 個 `.reveal` 中 **0 個**空白 | OK |
| V-04 | 列印時隱藏固定頁首 | 同上，讀取 `.site-header` 的 computed display | `display: none` | OK |
| V-05 | 列印時主按鈕可辨識 | 同上，讀取 `.btn-primary` 的 computed 樣式 | `color: rgb(0,0,0)`、`background: rgba(0,0,0,0)`、`border: rgb(102,102,102)` | OK |
| V-06 | 焦點指示器實際繪製 | 連按兩次 Tab 後讀取 `document.activeElement` 的 computed 樣式 | `outline-width: 3px`、`outline-color: rgb(63,64,59)` | OK |
| V-07 | 頁首半透明疊色後的實際背景 | 截取頁首區域並以 canvas 取樣三個無文字處的像素 | 左 `rgb(247,245,241)`、中 `rgb(247,246,241)`、右 `rgb(247,245,241)` | 見第 4 節 |

V-02 與 V-03 對應修正前的重大缺陷：`.reveal` 原本預設 `opacity: 0`，僅由 JavaScript 移除，導致 JavaScript 未執行時 19 個內容區塊永久不可見，列印時亦然。
