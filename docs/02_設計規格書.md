# 02 設計規格書

本文件記錄本網站**實際實作**的設計系統。所有數值均直接取自 `styles.css` 與 `index.html`，未經四捨五入或改寫。若欲確認出處，請對照 `styles.css` 中對應的選擇器。

- 依據：`index.html`、`styles.css` 的**工作目錄現況**（`f3b267f` 之後另有未提交的修正，本文件已反映該修正）
- 設計方向（`styles.css` 檔首註記）：日系文青／淺色極簡

---

## 1. 設計優先順序

`styles.css` 檔首明確記載了本專案的設計優先順序：

> 留白 > Typography > Grid > Photography > Color > Decoration

此順序的意義如下，後續所有規格均以此為判斷基準：

| 順位 | 要素 | 在本網站的具體表現 |
| --- | --- | --- |
| 1 | 留白 | 區段上下留白最大 120px、容器左右留白最大 48px、行高 1.9。留白是主要的視覺結構手段，不以框線或色塊分隔內容。 |
| 2 | Typography | 標題使用襯線體、內文使用無襯線體的雙字體對比；以字級、字重、字距（letter-spacing）建立層級。 |
| 3 | Grid | 以 CSS Grid 建立雙欄不對稱版面（如首屏 0.95fr : 1fr、頁尾 1fr : 1.4fr），避免均分帶來的呆板感。 |
| 4 | Photography | 圖片以大面積、圓角 14px、細框線呈現，配圖說明文字小而低調。 |
| 5 | Color | 色彩僅用於區分層級與強調，不用於裝飾。彩度極低。 |
| 6 | Decoration | 幾乎不使用裝飾元素。無陰影、無漸層背景、無圖示字型。唯一的裝飾性動態是導覽列底線與卡片浮起 2px。 |

**變更設計時的原則**：任何新增元素若必須依靠色彩或裝飾才能被辨識，代表前四項（留白、排版、格線、圖片）尚未用盡，應先回頭調整前四項。

### 3-2. 字體載入來源

透過 Google Fonts CDN 載入，宣告於 `index.html` 的 `<head>`，**刻意拆成兩個請求並採用不同的載入策略**：

拉丁字體（數 KB，`display=swap`）：

```
https://fonts.googleapis.com/css2?family=Inter:wght@400;500&display=swap
```

CJK 字體（數 MB，`display=optional`）：

```
https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500&family=Noto+Serif+TC:wght@400;500&family=Noto+Serif+JP:wght@400;500&display=optional
```

- 預先連線：`<link rel="preconnect">` 指向 `fonts.googleapis.com` 與 `fonts.gstatic.com`（後者帶 `crossorigin`）。
- **拆分理由**：拉丁字體體積小，`swap`（先以後備字體顯示、載入後替換）的成本可忽略；CJK 字體體積達數 MB，若同樣使用 `swap`，會在首次繪製數秒後才替換而造成整頁重排，因此改用 `optional`（未能即時載入時，本次瀏覽直接維持後備字體，不再替換）。
- Noto Serif TC **僅載入 400／500**。`styles.css` 中的標題一律使用 `font-weight: 500`，無任何位置使用 600。
- Noto Serif JP 供 `:lang(ja)` 規則使用。
- **注意**：本站依賴外部 CDN。若客戶端網路無法連線至 Google Fonts，字體會退回系統後備字體（`PingFang TC`／`Microsoft JhengHei` 等），版面比例會有差異但不致破版。因 CJK 採用 `display=optional`，在連線較慢的環境中**維持後備字體是預期行為，非缺陷**。

**無障礙上的注意事項**：所有輸入元素皆包在 `<label>` 之內（隱式關聯），未使用 `for`／`id` 明示關聯。此寫法在多數輔助技術上可正常運作，但實際驗證結果請填入 `03_測試規格書.md`。

**聚焦樣式**：`styles.css` 開頭定義了全站共通的鍵盤聚焦外框：

```css
:where(a, button, input, select, textarea, summary, [tabindex]):focus-visible {
  outline: 3px solid var(--text);
  outline-offset: 2px;
  border-radius: 4px;
}
```

- 使用 `:focus-visible` 而非 `:focus`，因此滑鼠點擊時不顯示外框，鍵盤操作時才顯示。
- `outline-offset: 2px` 讓外框落在元素外側的背景上，因此在橄欖綠按鈕上也能辨識。
- 以 `:where()` 包裹，優先權為 0，不會蓋過個別元件樣式。
- 唯一的例外是 `#main:focus`（略過連結的跳轉目標）刻意設為 `outline: none`，避免跳轉後出現整塊內容被框住的視覺。
- 輸入框另有聚焦時的框線變色（`--border` → `--olive`），屬於靜置狀態的樣式，與上述外框並存。

實際可辨識程度仍需於測試中確認，對比度實測項目見 `03_測試規格書.md` 第 9-1 節。

## 6. 動態規則

### 6-1. 緩動與時間

| 項目 | 值 |
| --- | --- |
| 共通緩動曲線 | `--ease: cubic-bezier(0.4, 0, 0.2, 1)` |
| 標準轉場 | 300ms（頁首、按鈕、卡片、導覽底線、漢堡線條位移） |
| 短轉場 | 260ms（導覽文字色、頁尾連結色、輸入框框線） |
| 極短轉場 | 200ms（漢堡鈕中間線的淡出） |
| 淡入 | 400ms（`.reveal` 的 opacity 與 transform） |

### 6-2. 捲動淡入

| 項目 | 值 |
| --- | --- |
| 預設狀態 | **`opacity: 1`、`transform: none`（可見）**。 |
| 隱藏狀態 | `html.js .reveal` 時才是 `opacity: 0`、`transform: translateY(12px)`。 |
| 完成狀態 | `html.js .reveal.is-visible` 為 `opacity: 1`、`transform: none` |
| 觸發條件 | `IntersectionObserver`，`threshold: 0.12` 且 `rootMargin: 0px 0px -8% 0px` |
| 執行次數 | 一次。觸發後 `unobserve`。 |
| 時間差 | `index × 40ms`，上限 160ms（`app.js` 直接寫入 `style.transitionDelay`） |
| 套用對象 | 服務卡片 10 張、現場記錄 3 則、流程步驟 5 項、服務地區圖 1 張（共 19 個元素） |

**`js` 類別的機制（重要）**：`index.html` 的 `<head>` 內、樣式表載入之前，有一段行內 script 為 `<html>` 加上 `js` 類別。淡入的隱藏狀態只在該類別存在時才生效。因此當 JavaScript 被停用、被封鎖或載入失敗時，19 個內容區塊會維持可見，不會永久停留在透明狀態。列印時同理。

**`rootMargin` 的用意**：單靠 `threshold: 0.12` 時，高度超過視窗的元素永遠無法達成 12% 的比例而不會觸發；加上底部 −8% 的邊界後，觸發同時具備位置條件。

**特性偵測**：`app.js` 在不支援 `IntersectionObserver` 的環境中，會直接為全部 `.reveal` 加上 `is-visible`，不會讓內容停在透明狀態。

### 6-3. 導覽列現在位置判定

`IntersectionObserver` 的 `rootMargin: -45% 0px -50% 0px`（`app.js` 中以 `TOP_CUT = 45`、`BOTTOM_CUT = 50` 兩個常數組成），即以視窗上方 45% 至下方 50% 之間的水平帶（約為畫面中央 5% 的範圍）判定。進入該帶的區段對應的導覽連結會加上 `is-active`。

**不變條件**：`TOP_CUT + BOTTOM_CUT` 必須小於 100。等於 100 時判定帶高度為零，觀察器永不觸發，導覽高亮會在完全沒有錯誤訊息的情況下失效。`app.js` 中已就此加上註解。

### 6-4. 減少動態偏好（`prefers-reduced-motion: reduce`）

作業系統設定為減少動態時：

- 所有元素（含 `::before`／`::after`）的 `transition-duration` 與 `animation-duration` 強制為 `0.01ms`。
- `transition-delay` 與 `animation-delay` 亦強制為 `0ms`。這是必要的：`app.js` 以行內樣式寫入 `transition-delay`，非 `!important` 的規則無法覆蓋。
- `scroll-behavior` 強制為 `auto`（錨點跳轉不再平滑捲動）。
- `.reveal` 與 `html.js .reveal` 皆直接以 `opacity: 1`、`transform: none` 顯示，不再有淡入。

此規則以 `!important` 指定，優先度高於個別元件設定。

### 6-5. 動態設計的原則

本網站的動態一律屬於「回饋」而非「演出」。位移量最大 12px（淡入）、2px（卡片浮起）、1px（按鈕浮起），無旋轉、無縮放、無視差捲動。新增動態時應維持此規模。

## 7. 雙語小標的設計運用

各區段開頭配置了兩層小標：上層為日文（襯線體、14px、`--olive`、字距 0.14em）、下層為英文（Inter、10.5px、`--muted`、字距 0.2em、全大寫）。服務項目區段的兩個群組標題亦以相同手法配置日文小標（`.group-ja`）。

**這是刻意的視覺設計元素，並非多語系功能。** 頁面主要語言為繁體中文（`<html lang="zh-Hant">`），日文文字僅作為呼應「日系文青／淺色極簡」風格方向的裝飾性標記，不提供語言切換，亦無對應的日文版頁面。

實際使用的日文標記如下：

| 位置 | 日文標記 | 併記的英文 |
| --- | --- | --- |
| 首屏 | 暮らしの技術 | Technology for everyday life |
| 關於我們 | 私たちについて | About |
| 服務項目 | 仕事の内容 | Services |
| 服務項目／群組一 | 現場工事 | （無） |
| 服務項目／群組二 | デジタル | （無） |
| 現場記錄 | 現場の記録 | Works |
| 服務流程 | 仕事の流れ | Process |
| 服務地區 | 対応地域 | Area |
| 聯絡我們 | お問い合わせ | Contact |

**語言標註**：上表所有日文文字皆已於 `index.html` 中以 `lang="ja"` 標註。因此：

- 螢幕報讀器可切換為日文發音規則朗讀，不會以中文規則讀出假名。
- `styles.css` 的 `:lang(ja)` 規則會為這些文字套用日文明朝體（Noto Serif JP 等），避免日文漢字以繁體字形呈現（例如「対応地域」在繁體字體下會顯示為「對應地域」的字形）。

實際朗讀結果仍需於螢幕報讀器測試中確認（`03_測試規格書.md` T-913）。
