## 2. 本機預覽

### 2-1. 最簡單的方式

直接以瀏覽器開啟 `index.html`（雙擊檔案，或拖曳至瀏覽器視窗）。

多數內容可正常檢視，但以 `file://` 協定開啟時，部分瀏覽器對本機檔案有安全限制，可能影響字體載入或 JavaScript 行為。**正式確認請務必使用下一節的本機伺服器方式。**

### 2-2. 以本機伺服器預覽（建議）

在專案根目錄執行下列任一指令，然後以瀏覽器開啟畫面上顯示的網址（通常為 `http://localhost:8000` 或 `http://localhost:3000`）。

若已安裝 Python 3：

```
python3 -m http.server 8000
```

若已安裝 Node.js：

```
npx serve .
```

停止伺服器請按 `Ctrl + C`。

> 上述指令為一般常見做法，**本文件撰寫時未在客戶端環境實際執行驗證**。實際可用的指令依維護人員的環境而定。首次執行時請確認結果，並將確認結果記錄於此：【需填寫】

### 2-3. 修改後的確認重點

每次修改後，最低限度請確認下列四點：

1. 桌機寬度（1440px 左右）與手機寬度（390px 左右）皆無破版。
2. 瀏覽器開發者工具的 Console 沒有紅色錯誤訊息。
3. 導覽列的五個連結皆可正常跳轉。
4. 修改處的文字沒有錯字、沒有殘留的佔位文字。

完整確認項目請參照 `03_測試規格書.md`。

### 4-1. 現況

`images/` 內的 6 個 SVG **全部是以品牌色階製作的漸層色塊佔位圖，不是實際照片**。正式上線前必須全部替換。

### 4-2. 各圖片位置的規格

### 4-3. 需特別留意的兩個裁切位置

**`about.svg`（關於我們）**
高度被限制在 460px 並以 `cover` 填滿，因此上下會被大幅裁掉，只留中央的橫向帶狀區域。請選擇**主體位於畫面垂直中央**的照片。

**`work-01.svg`（現場記錄主圖）**
桌機版強制裁切為直式 3:4，平板／手機版強制裁切為橫式 4:3。同一張照片必須在兩種比例下都成立，因此請選擇**主體集中在畫面正中央、四周留有餘裕**的照片。若難以兼顧，建議準備一張本身就接近正方形的照片。

### 4-4. 替換步驟

**方式 A：沿用檔名（建議，最簡單）**

1. 準備照片，命名為與原檔完全相同的名稱（含副檔名）。
2. 覆蓋 `images/` 內的舊檔。
3. 不需修改 `index.html`。

若使用 JPEG 或 PNG，副檔名會改變（例如 `hero.svg` → `hero.jpg`），此時仍需修改 `index.html` 中的 `src`。

**方式 B：使用新檔名**

1. 將照片放入 `images/`。
2. 編輯 `index.html`，將對應的 `src="./images/舊檔名"` 改為新檔名。
3. **同時修改 `width` 與 `height` 屬性為新照片的實際像素尺寸。** 這兩個屬性用於避免載入時的版面跳動，數值錯誤會造成版面位移。

**兩種方式共通的必辦事項**：

替換為實際照片後，**必須補上 `alt` 替代文字**。目前 6 張圖的 `alt` 皆為空字串（視為裝飾圖）。實際照片承載資訊時，空的 `alt` 會讓螢幕報讀器使用者無法得知內容。

```
<img src="./images/work-01.jpg" alt="透天住宅外牆上重新配置後的監視鏡頭" width="1700" height="1275" />
```

### 4-5. 照片格式與檔案大小的建議

| 項目 | 建議 |
| --- | --- |
| 格式 | JPEG（照片）。若瀏覽器支援情形允許，WebP 可進一步縮小檔案。 |
| 單檔大小 | 建議壓縮至 300KB 以下。本網站無圖片延遲載入（lazy loading）機制，所有圖片在載入時一併下載，檔案過大會直接影響首次顯示速度。 |
| 色調 | 本網站為低彩度的米白／橄欖綠色系。過度鮮豔或高對比的照片會破壞整體調性，建議降低飽和度後使用。 |
| 肖像權與同意 | 頁面上已明示「實際案場照片與客戶資訊需經同意後才會公開」。刊登前**務必**取得客戶同意，並確認照片中無可識別的個人、車牌、門牌號碼等資訊。 |

## 5. 修改文字內容

### 5-1. 修改前的注意事項

1. **務必先備份 `index.html`**（複製一份為 `index.html.bak` 等）。
2. 請使用純文字編輯器（VS Code、Sublime Text、Notepad++ 等）。**不可使用 Word 等文書軟體**，會破壞檔案編碼。
3. 檔案編碼為 UTF-8，儲存時請維持 UTF-8。
4. **只修改標籤之間的文字**，不要更動 `<` 與 `>` 之間的部分。

```
<h4>監視系統</h4>
     ↑↑↑↑ 只修改這裡
```

### 5-2. 各內容的所在位置

`index.html` 中以註解標示了各區段的起點，可用編輯器的搜尋功能快速定位。

| 內容 | 搜尋關鍵字 | 說明 |
| --- | --- | --- |
| 瀏覽器分頁標題 | `<title>` | 同時影響搜尋結果的標題。 |
| 搜尋結果的說明文 | `name="description"` | 建議 120 字以內。 |
| 社群分享標題／說明 | `og:title` / `og:description` | 分享至社群時顯示的文字。 |
| 首屏標題與導言 | `hero` 註解 | `<br />` 為手動換行，修改文字長度後請重新確認換行位置。 |
| 關於我們內文 | `about` 註解 | 三個 `<p>` 段落。 |
| 服務項目 | `services` 註解 | 卡片標題在 `<h4>`，說明在 `<p>`。 |
| 現場記錄 | `works` 註解 | 分類在 `.work-meta`，標題在 `<strong>`，補充在 `<em>`。 |
| 服務流程 | `process` 註解 | 五個 `<li>`。 |
| 服務地區 | `area` 註解 | 地區名稱在 `.area-list` 的各 `<li>`。 |
| 聯絡資訊 | `contact-meta` | 電話、電子郵件、服務時間（目前為佔位文字）。 |
| 表單選項 | `<select` | 下拉選單的選項。 |
| 頁尾公司資訊 | `footer-note` | 統一編號、地址、電話（目前為佔位文字）。 |

### 5-3. 安全的修改與應避免的修改

| 修改內容 | 安全性 | 備註 |
| --- | --- | --- |
| 標籤之間的文字 | 安全 | 最常見的更新作業。 |
| 增減服務卡片 | 需注意 | 複製整個 `<article class="card reveal">…</article>` 區塊即可增加。**卡片編號（`.card-no`）需手動修改**。卡片數量改變時，欄數配置的視覺平衡可能需重新確認（弱電群組為 3 欄、數位群組為 4 欄）。 |
| 增減流程步驟 | 需注意 | 同上，編號需手動修改。 |
| 增減服務地區 | 安全 | 複製 `<li>` 即可。 |
| 增減表單選項 | 安全 | 複製 `<option>` 即可。 |
| 增加新的區段 | 需謹慎 | 新區段的 `id` 若要加入導覽列，需同時修改桌機導覽列與行動版抽屜選單**兩處**。 |
| 修改 `class` 屬性 | **避免** | 會破壞樣式與 JavaScript 行為。 |
| 修改 `id` 屬性 | **避免** | 會破壞所有錨點連結與導覽高亮。 |
| 修改 `data-` 屬性 | **避免** | `app.js` 依靠這些屬性運作。 |
| 修改 `<script>`／`<link>` 標籤 | **避免** | 會導致樣式或行為完全失效。 |

### 5-4. 修改後必須確認

1. 以瀏覽器開啟，確認修改處正確顯示。
2. 確認修改處前後的版面沒有跑掉。
3. 手機寬度下再確認一次（尤其是手動換行 `<br />` 的位置）。
4. 開發者工具 Console 無錯誤。

## 6. 將聯絡表單串接為可實際收件

### 6-1. 現況（務必理解）

**目前的表單完全不會送出任何資料。** `app.js` 中的處理僅為：阻擋預設送出行為 → 按鈕文字改為「已收到，待正式串接」→ 停用按鈕 → 2.4 秒後復原。

**沒有寄送郵件、沒有儲存資料、沒有通知任何人。** 使用者填寫的內容在按下送出後即消失。

頁面上的註記也已明示此點：「此表單為前端示範，正式上線前需串接表單服務、Email 通知、LINE 官方帳號或 CRM 才會實際送出。」

> **上線判斷**：若在未串接的狀態下上線，使用者會誤以為已送出諮詢而等待回覆，導致商機流失與信任受損。若情況上必須先行上線，**請務必修改表單註記文字，明確告知「本表單目前僅供參考，請改以電話聯絡」**，並將電話號碼顯著呈現。

### 6-2. 串接選項

以下為頁面註記中提及的四個方向。實際採用哪一種，請依客戶的作業流程決定。

| 選項 | 概要 | 優點 | 需考量之處 |
| --- | --- | --- | --- |
| **A. 表單服務** | 使用第三方表單託管服務，將 `<form>` 的 `action` 指向該服務提供的網址。 | 不需自建後端，導入最快。多數服務內建垃圾訊息過濾與收件備份。 | 需申請帳號、可能有免費額度限制、個資由第三方保管（需確認隱私政策）。 |
| **B. Email 通知** | 由伺服器端程式（PHP 或無伺服器函式）接收表單並寄送通知信至公司信箱。 | 完全自行掌控。收件流程與現行郵件作業一致。 | 需要可執行程式的主機環境（純靜態託管無法使用）。需處理垃圾訊息、寄信網域驗證（SPF／DKIM）以避免進入垃圾信匣。 |
| **C. LINE 官方帳號** | 不使用表單送出，改為在頁面上放置 LINE 官方帳號的加好友連結或 QR Code，引導使用者直接以 LINE 洽詢。 | 台灣使用者接受度高。可即時對話、方便傳送現場照片，符合本業務「請提供設備照片」的需求。 | 需申請並經營 LINE 官方帳號。表單本身的存在意義需重新檢討（可保留表單並同時提供 LINE 入口）。 |

## 7. 變更色彩

### 7-1. 基本作業

全站色彩集中定義於 `styles.css` 開頭的 `:root` 區塊。修改該處的色碼，全站對應位置會一併變更。

```css
:root {
  --bg: #f7f5f0;      /* 頁面背景 */
  --bg-2: #efece5;    /* 交替區段背景 */
  --card: #fcfbf8;    /* 卡片、表單背景 */
  --text: #3f403b;    /* 主要文字 */
  --text-2: #77776f;  /* 次要文字 */
  --muted: #a5a399;   /* 弱化文字 */
  --sage: #a8b5a2;    /* 強調色（淺） */
  --olive: #7e8c75;   /* 強調色（深） */
  --beige: #d8cdbd;   /* 目前未使用 */
  --brown: #a38f7a;   /* 目前未使用 */
  --border: #e4e0d8;  /* 框線 */
}
```

各屬性的詳細用途請參照 `02_設計規格書.md` 第 2 章。

### 7-2. 必須一併手動修改的位置

下列色值**未使用自訂屬性**，直接寫死在檔案中。變更調色盤時若遺漏，會出現色調不一致。

| 位置 | 目前值 | 說明 |
| --- | --- | --- |
| `styles.css`：`.btn-primary:hover`、`.contact-form button:hover` | `#6f7c67` | 主要按鈕的滑入色。應為 `--olive` 的加深版。 |
| `styles.css`：`.btn-primary`、`.contact-form button`、`.drawer-cta` 的 `color` | `#fdfcf9` | 深色按鈕上的文字色。 |
| `styles.css`：`.card:hover`、輸入框 `:focus` 的 `background` | `#fff` | 卡片與輸入框的強調背景。 |
| `styles.css`：`.skip-link` 的 `color` | `#fff` | 略過連結的文字色。 |
| `styles.css`：`.site-header` 的 `background` | `rgba(247, 245, 240, 0.82)` | `--bg` 的半透明版。**變更 `--bg` 時必須同步修改此處的 RGB 值**，否則頁首會與頁面底色不一致。 |
| `styles.css`：`.site-header.is-scrolled`／`.is-open` 的 `background` | `rgba(247, 245, 240, 0.95)` | 同上。 |
| `index.html`：`<meta name="theme-color">` | `#F7F5F0` | 行動瀏覽器的網址列色彩。應與 `--bg` 一致。 |
| `images/*.svg` | 各圖檔內的漸層色 | 佔位圖內含 `#FCFBF8`、`#E4E0D8`、`#EFECE5`、`#D8CDBD`、`#A8B5A2`、`#A38F7A` 等色。替換為實際照片後即不再相關。 |

### 7-3. 變更色彩後的必要確認

1. **對比度**：淺色系設計對比餘裕本就不大，加深或提亮任一色都可能使小字級文字變得難以閱讀。請以對比度檢測工具重新量測 `03_測試規格書.md` 第 9-1 節的六個組合。
2. 深色按鈕上的淺色文字是否仍清晰。
3. 頁首在捲動前後、與其下方內容重疊時是否仍可辨識。
4. 框線是否仍可見（框線色與背景色過於接近時，卡片輪廓會消失）。

| `scroll-behavior: smooth` | 錨點捲動 | 改為瞬間跳轉（功能不受影響）。 |
| `inset` 簡寫 | 頁首、抽屜定位 | 定位失效，版面破壞。 |

## 10. 疑難排解

| 現象 | 可能原因與處理 |
| --- | --- |
| 修改後看不到變化 | 瀏覽器快取。請強制重新整理（`Ctrl/Cmd + Shift + R`）。 |
| 版面完全跑掉 | `styles.css` 未載入。確認檔名、檔案位置與 `index.html` 中的 `<link>` 路徑。 |
| 抽屜選單、淡入無反應 | `app.js` 未載入或發生錯誤。開啟開發者工具 Console 確認錯誤訊息。 |
| 中文變成亂碼 | 檔案編碼非 UTF-8。以純文字編輯器另存為 UTF-8。 |
| 圖片不顯示 | 檔名大小寫不符（伺服器多半區分大小寫）或路徑錯誤。 |
| 字體看起來不對 | 無法連線至 Google Fonts。確認網路環境或防火牆設定。 |
| 點擊導覽後標題被頁首遮住 | 若曾修改 `--header-height` 而未同步調整，請確認 `scroll-padding-top` 的設定。 |
| 表單送出後沒收到信 | **這是正常的**。表單尚未串接後端。見第 6 節。 |
